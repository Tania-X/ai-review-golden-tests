# ai-review 测评体系评审(讨论记录)

> 2026-08-13 复盘讨论 · 对 golden 测试 + 单测体系的合理性审视
> 状态: 结论沉淀, 改进项按优先级排队, 未实施
> 注意: 本文件是"测评方法论评审", 不是场景标准答案(答案在 golden-contract.md);
>       不进任何场景分支的审查上下文(context_files 已排除 docs/**)。

## 一、骨架合理(保留)

1. **三层测试结构**: 单测(mock, 锁代码逻辑) → 闭环脚本(端到端 mock) → golden(真实环境量化), 层次清晰
2. **防剧透设计**: 代码不剧透 + 契约分离 + 答案不可见, 测评有效性的根基
3. **Level 0/1 分层 + 正/负/边界样本分类**: refuse/agree 状态机自洽

## 二、五个关键短板

### 短板 1: 样本量不足, 统计意义弱(最致命)

- 正样本仅 3 个(bug/security/convention), 负样本 2 个, 边界 1 个
- 3 个样本算精确率/召回率, 一次运行基本无统计意义; LLM 非确定 → 单次 pass/fail 可能是运气
- 风险: "每次改 prompt 跑一遍看退化"的价值落空(分不清 prompt 退化 vs 随机波动)

**改进**: 每个 case 跑 N 次报 pass 率(非单次); 场景扩充到 15~20 个。

### 短板 2: 断言粒度太粗, 会放过"答非所问"

- 当前断言"报了几个 error/warn"; 报对 severity ≠ 报对缺陷
- case-bug 期望报 error, AI 报任意 error(哪怕是幻觉)数量上仍算 pass
- 测的是"级别"而非"能力"

**改进**: expected.json 标注缺陷**位置锚点**(file:line 或特征关键词), 断言 AI 报的 issue 命中该位置。

### 短板 3: prompt 是测评盲区

- 单测 mock 掉 LLM → prompt 好坏完全测不到
- golden 能测 prompt, 但样本少, 兜不住细微退化
- prompt 是对质量影响最大、却最缺回归保障的部分

**改进**: review_focus 每条对应一个场景, prompt 改哪条能看到哪条对应 case 的变化。

### 短板 4: parser 与评论格式隐式耦合

- 驱动器 parser 靠正则解析 `### 🔴 Error (N)`; format_comment 一改分组标题, parser 静默失效
- 失效表现: 解析出 0 个 issues → 所有场景误判, 且无报错
- 上轮加编号 `1.` 没坏是运气(改的是列表项不是标题), 不是契约

**改进**: 评论格式定义成显式契约, parser 与 format_comment 共享格式定义; 加测试锁住"format_comment 输出能被 parser 解析"。

### 短板 5: judge 打分缺 ground truth 校准

- golden 测的是"审查 LLM + judge"的混合结果, judge 本身准不准未独立验证
- 缺人工标准分: 人工给各场景审查结果打标准分, 对比 judge 打分看相关性

**改进**: 建立 ground truth 评分集(人工标注), 校准 judge 的 pass_score 与打分倾向。

## 三、结构性观察

当前测评测的是**端到端表现**, 未区分"代码逻辑 bug"与"prompt 质量"。出问题难定位。应明确分工:

```
单测   → 锁代码逻辑(parser/config/质量门循环)
golden → 锁 prompt 质量(审查重点覆盖 + 精确率/召回率)
闭环   → 锁集成(refuse→fix→agree 链路)
```

## 四、"自我演进"的隐患

- "期望演进纪律(防放水)"靠人工自觉, 无机制保证
- 风险: 跑不过就放宽 expected, 把测评调成永远通过
- 缺**期望变更审计**: 每次改 expected.json 记录"为什么改、哪次运行暴露了问题"

## 五、改进优先级

| 优先级 | 事项 | 理由 |
|--------|------|------|
| P0 | 断言升级到"缺陷位置匹配" | 否则测的是级别不是能力, 结论误导 |
| P0 | parser/format 契约化 + 锁死测试 | 静默失效是隐蔽的雷 |
| P1 | 每个 case 跑 N 次报 pass 率 | 抵消随机性 |
| P1 | review_focus 每条对应一个场景 | 让 prompt 回归有抓手 |
| P2 | judge ground truth 校准 | 重要但工作量大 |
| P2 | 真实 PR 回放集(devops-dashboard 历史 PR) | 比人造场景更贴近实战 |
